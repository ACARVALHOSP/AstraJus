cnj-processual · servidor MCP

Funcionalidades

Servidor MCP para consulta processual judicial brasileira, usando as APIs públicas do CNJ: DataJud (metadados e movimentações) e DJEN (publicações e certidões). Pode rodar localmente ou como serviço compartilhado com acesso por token.

Ferramentas (tools)

O servidor expõe três ferramentas que o modelo pode chamar.

DataJudconsultar_processo_datajud

Consulta metadados de um processo: classe, órgão julgador, data de ajuizamento, grau e a lista de movimentações.

ParâmetroDescrição
tribunal (obrigatório)Sigla minúscula, como tjsp, trf1 ou stj.
numero_processo (obrigatório)Número CNJ de 20 dígitos, com ou sem máscara.
  • Cada resultado traz grau e grau_descricao (por exemplo, "1º grau" ou "2º grau"). Um mesmo número pode aparecer mais de uma vez, uma para cada grau.
  • Movimentações com código, nome, data e, quando existir, complementos tabelados.
  • Processo não encontrado retorna encontrado: false, que não é erro.
  • Timeout de 70 segundos, com nova tentativa em timeout, 429 e 502/503/504.
  • Não retorna nomes de partes, por política de proteção de dados da API.

DJENconsultar_publicacoes_djen

Consulta publicações e intimações do Diário de Justiça Eletrônico Nacional. Não exige autenticação na API do CNJ.

ParâmetroDescrição
numero_processo20 dígitos, máscara removida automaticamente.
numero_oab, uf_oabOAB do advogado e UF com 2 letras.
sigla_tribunalPor exemplo, TJSP.
data_disponibilizacao_inicio, data_disponibilizacao_fimIntervalo em AAAA-MM-DD. O início não pode ser posterior ao fim.
pagina, itens_por_paginaPaginação. Padrão: página 1, 50 itens.
  • Ao informar processo ou OAB é obrigatório, ou ambos.
  • O texto da publicação vem convertido de HTML para texto puro, com entidades decodificadas.
  • Cada item traz o hash, que é usado para baixar a certidão.
  • Timeout de 30 segundos, com uma nova tentativa em timeout, erro de conexão e 500/502/503/504.
  • HTTP 403 significa bloqueio geográfico: o serviço só funciona a partir de IPs do Brasil.

DJENbaixar_certidao_djen

Gera a certidão em PDF de uma publicação e devolve um link de download temporário.

  • Parâmetro: hash, vindo de consultar_publicacoes_djen.
  • Resposta com link_download, válido por 15 minutos, assinado e sem exigir token. O PDF abre direto no navegador.
  • O PDF é confirmado pela assinatura %PDF antes de ser salvo.
  • Certidões com mais de 7 dias são removidas do servidor a cada novo download.

Compartilhado (HTTP)Várias pessoas, com acesso individual por token.Endpoint /mcp em HTTPS, com Authorization: Bearer ou o conector OAuth do Claude.
Exemplo de endereço do serviço compartilhado: https://exemplo.sslip.io/mcp. O endereço real é definido por quem hospeda o servidor.

Usuários e tokens

Cada pessoa tem um token próprio. O servidor guarda apenas o hash SHA-256 de cada token, nunca o valor original.

  • Criar: pela linha de comando (--criar-usuario NOME) ou pela página administrativa. O token aparece uma única vez.
  • Listar: --listar-usuarios, sem mostrar tokens.
  • Revogar: --revogar-usuario NOME. O efeito é imediato, sem reiniciar o servidor.
  • Os nomes aceitam letras minúsculas, números, ., _, -, + e @.
  • Cada requisição autenticada fica no log com o nome do usuário, o método e o caminho. O conteúdo das consultas não é registrado.

Página administrativa (/admin)

Disponível quando CNJ_MCP_ADMIN_TOKEN está definido (mínimo de 24 caracteres). Permite criar e revogar usuários pelo navegador. Sem o token administrativo, a página não mostra a lista de usuários.

Cadastro por e-mail (/cadastro)

Quem quer acesso pede o próprio token. Disponível quando o SMTP está configurado.

  1. Termos de uso: o texto é mostrado primeiro, e a pessoa precisa marcar a caixa de aceite. A versão dos termos e a data do aceite ficam registradas.
  2. E-mail: a pessoa informa o endereço e confirma o reCAPTCHA ("não sou um robô").
  3. Token: o token chega só no e-mail informado. A página nunca mostra o token e avisa para anotá-lo, porque ele não será exibido novamente.
  • A resposta é a mesma para qualquer e-mail válido, então ninguém descobre quais endereços já têm acesso.
  • Pedir de novo gera um token novo e invalida o anterior. É o caminho para quem perdeu o token.
  • Quem foi revogado pelo administrador não recebe token novo por esse caminho.
  • O token só é enviado depois que o captcha é validado no servidor, e o e-mail só é enviado se o envio não falhar.

Conector do Claude (OAuth 2.1 com PKCE)

Permite adicionar o servidor em Personalização → Conectores, no Claude Desktop ou no Claude web, sem editar arquivos.

  1. O Claude registra um cliente em /oauth/register. Só são aceitos callbacks de claude.ai, claude.com e de localhost.
  2. A pessoa abre a página de autorização e cola o próprio token.
  3. O servidor devolve um código de uso único, que vale por 5 minutos.
  4. O Claude troca o código por um access token em /oauth/token. A troca exige PKCE (S256).
  5. O access token vale por 30 dias. Revogar o usuário invalida também os access tokens dele.

Os metadados de descoberta ficam em /.well-known/oauth-protected-resource e /.well-known/oauth-authorization-server.

Painel web (/app)

Página própria, sem relação com o Claude, para quem quer consultar direto no navegador. Fala o protocolo MCP (Streamable HTTP) em JavaScript puro, com o token que a pessoa cola no topo da página. Usa a folha de estilos do Carbon, a mesma do /admin.

  • Token local: fica só no navegador de quem usa, em localStorage (se a pessoa marcar "lembrar") ou só na memória da aba. Nunca é enviado a nenhum serviço além do próprio servidor.
  • Duas abas: consulta de processo (DataJud) e de publicações (DJEN), com os mesmos campos das tools.
  • Espera visível: um indicador com o tempo decorrido, porque a consulta ao DataJud pode levar até dois minutos.
  • Reconexão de sessão: se a sessão MCP expirar no servidor (por exemplo, após um reinício), o painel reinicia a sessão sozinho e repete a chamada uma vez.
  • Certidão: o botão "Baixar certidão" chama a tool e abre o link de download em uma aba nova.
  • Sem CDN: todo o JavaScript e o CSS são servidos pelo próprio servidor (static/app.js, static/app.html), porque a CSP não libera scripts de terceiros.

Instaladores

Scripts em instalador/ configuram o cliente sem editar JSON à mão.

  • Windows: instalar-windows.ps1
  • macOS e Linux: instalar-unix.sh

Validam o token no servidor antes de gravar qualquer configuração, fazem backup do arquivo do Claude Desktop e mantêm as outras configurações. Aceitam CNJ_TOKEN para uso sem interação.

Limitações

  • Nomes de partes: o DataJud não expõe partes. O DJEN pode trazer nomes e OABs, e o uso deve seguir a finalidade legítima da consulta.
  • Busca por OAB: tribunais gravam a OAB com sufixos diferentes (123456, 123456-O), e a busca pode não encontrar tudo.
  • Lentidão do DataJud: consultas podem levar mais de um minuto em horários de pico.
  • Bloqueio geográfico: o DJEN só responde a partir do Brasil.
  • Limites em memória: os contadores de uso ficam no processo. Com mais de uma instância, cada uma conta separadamente.
  • Certidões no servidor: os PDFs ficam no servidor e são apagados após 7 dias.
  • Chaves reinicializadas: sem CNJ_MCP_SEGREDO, links de certidão emitidos antes de um reinício deixam de valer.
